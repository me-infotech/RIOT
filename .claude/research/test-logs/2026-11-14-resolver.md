# Test log 2026-11-14 — dependency resolution without Make (roadmap P6, D25)

Decisions (user, D25): dependency rules as data translated from the make
files, Python resolver evaluating them in Make's order, translator for all
dependency files, hello-world and gnrc_networking. Code: `build-poc/resolver/`
(`translate_deps.py`, `makeexpr.py`, `resolver.py`, README). Tree:
`RIOT_Test` working tree (rules translated from it). Host: GNU Make 4.3,
Python 3.12.3, PyYAML 6.0.1. Evidence: `.claude/research/resolver/`
(`SHA256SUMS`).

## 1. Translation of RIOT's dependency files

| | Count |
|---|---:|
| files translated (all `Makefile.dep`, `Makefile.features`, `*.dep`, `Makefile.default`, 4 pipeline files, and the 97 files they include) | 1196 |
| files fully translated | 1191 |
| statements | 9847 |
| structured rules (filter/eq/def conditions, assignments with plain words, includes) | 9667 |
| expression fallback (conditions/values with Make functions kept as expression) | 168 |
| unsupported | 12 (5 files) |

Unsupported (`translate-unsupported.json`): `$(call target-export-variables,…)`
in three `stdio_*`/`usb_board_reset` helper files, make rules (`preflash-delay`,
`term-delay`) in `makefiles/tools/usb_board_reset.mk`, `define NEWLINE` in
`utils/ansi_special.mk`, `$(shell …)` in `cpu/stm32/stm32_info.mk`. None is
reached for the two applications. Most of the fallback expressions are in
the included helper libraries (`makefiles/utils/*.mk`, user functions with
`$1`), not in the `Makefile.dep` files themselves (first run without
helpers: 9227 structured, 53 fallback, 1 unsupported of 9281).

Findings on the way: `Makefile.dep` files include engine parts
(`makefiles/features_check.inc.mk` from `sys/ztimer`, `sys/psa_crypto`) and
helper libraries (`stdio.inc.mk` → `utils/strings.mk`); the resolver
implements the features check in Python and treats colour helpers as
without effect. RIOT passes `DEVELHELP` into the resolution
(`cpu/cortexm_common/Makefile.dep`: `ifeq (1, $(DEVELHELP))` →
`FEATURES_OPTIONAL += cortexm_mpu` → `mpu_stack_guard`), so scalar
settings of `riot-app.yaml` are inputs of the resolver.

| hello-world | native64 | 42 = 42 | 0 = 0 | 6 = 6 | – | – | – |
| gnrc_networking | native64 | 164 = 164 | 0 = 0 | 10 = 10 | – | – | – |

All sets identical. Development history (nrf52840dk, hello-world modules):
51 (substitution reference `$(USEMODULE:%=$(RIOTBASE)/drivers/%/…)` did not
expand `$(RIOTBASE)` → `drivers/periph_common/Makefile.dep` not read) → 60
(`DEVELHELP` not passed) → 61.

## 3. Time

Median of 10 runs (gnrc_networking, nrf52840dk, host): resolver 227 ms
(includes loading the 1.4 MB rule file); translation of all files 231 ms
(median of 5). Make's resolution in the container was 177 ms
(`2026-11-14-build-layer-nrf52840dk.md` §6) — same order of magnitude.

## Reading [inference]

RIOT's dependency model can be expressed as ordered data rules: 98 % of
the statements are simple structured rules, and evaluating them in Make's
order reproduces Make's result exactly for both applications on both
boards. The remaining Make-specific parts are the fallback expressions in
helper libraries and the order dependence of negative conditions, which
the data keeps (D25: Make order).
